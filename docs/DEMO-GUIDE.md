## ลำดับสาธิตที่แนะนำ (15 นาที)
1. **ผู้ปกครอง (มือถือ)** `parent01` → `/pickup` → “ฉันกำลังไปรับ” (ใช้ตำแหน่งจำลอง) → เห็นแผนที่/ETA
2. **เจ้าหน้าที่ประตู (จอใหญ่)** `gate01` → เห็นผู้ปกครองขึ้นคิวสดโดยไม่ต้องรีเฟรช → ยืนยันตัว → เรียกนักเรียน (มีเสียงเรียกถ้ากดเปิดเสียง)
3. **ผู้ปกครอง** เห็น “ครูเรียกนักเรียนแล้ว” ทันที → **ประตู** กด “ส่งนักเรียนแล้ว” → ผู้ปกครองเห็นว่าส่งแล้ว
4. **ผู้รับแทน** `parent09` → `/passes` สร้างรหัส+QR → ประตูพิมพ์รหัสตรวจและยืนยัน → ใช้ซ้ำไม่ได้
5. **ความปลอดภัย** `schooladmin` → `/admin/custody` ติดธงห้ามปล่อย → จอประตูขึ้นป้ายและปุ่มส่งถูกปิด (เหตุผลเห็นเฉพาะผู้ดูแล)
6. **ฉุกเฉิน** `schooladmin` → `/admin/announce` ประกาศ + พักการรับ → ผู้ปกครองเห็นแบนเนอร์ จอประตูปิดปุ่ม → เปิดรับอีกครั้ง
7. **จอ TV** `/admin/tv` เพิ่มจอ → เปิดลิงก์ลับในหน้าต่างใหม่ → เรียกนักเรียนแล้วชื่อเล่น+ห้องขึ้นจอ (ไม่มีนามสกุล/ทะเบียน)
8. **ผู้บริหาร** `/admin/analytics` (เวลารอที่ประตู, ชั่วโมงแน่น) · `/admin/audit` (ใครทำอะไรเมื่อไร ส่งออก CSV)
9. **แพลตฟอร์ม** `superadmin` → `/platform/flags` สวิตช์ฟีเจอร์ · `/platform/brand` เปลี่ยนชื่อ/โลโก้

เล่นซ้ำเต็มรูปแบบ (สร้างรอบใหม่): `pnpm demo:simulate` (ต้องมีคีย์ใน env) — ขั้นตอนอนุมัติคำขอ 3 รายการแรกจะไม่ผ่านซ้ำเพราะอนุมัติไปแล้ว ส่วนที่เหลือสร้างธุรกรรมชุดใหม่

## ข้อควรระวัง
- **บัญชีสาธิตใช้รหัสผ่านเดียวกันและเป็นรหัสที่เดาง่าย** รวมถึง Super Admin บน production — ใช้เฉพาะช่วงสาธิต ถ้าไม่ได้สาธิตแล้วให้ลบทันที (หรือขอให้ผมปิดบัญชี)
- LINE จริง, GPS ขณะขับรถ, เสียงภาษาไทยบนจอจริง ทดสอบจากที่นี่ไม่ได้ (การสาธิตใช้ตำแหน่งจำลอง/การแจ้งเตือนในแอป)

## ลบข้อมูลสาธิตก่อน go live
```bash
NODE_USE_ENV_PROXY=1 node scripts/demo-data.mjs --remove
# เมื่อเจ้าของอนุมัติให้ลบ audit ของข้อมูลสาธิตด้วย:
NODE_USE_ENV_PROXY=1 node scripts/demo-data.mjs --remove --purge-audit
```
